# Strudelizer

Strudelizer turns MIDI files, chord sheets, guitar tabs, Guitar Pro files and
MusicXML scores into [Strudel](https://strudel.cc) live-coding patterns that play on
strudel.cc with no edits. It works like a compiler:

```
importers            Song IR (JSON)       passes                  emitters
  midi        ──▶    versioned,     ──▶   quantize, dedupe_bars   ──▶  strudel (.js)
  chordsheet         schema-checked       arrange, detect_sections     midi (.mid)
  ascii_tab                               transpose, remap_drums       ir_json (.json)
  guitarpro   [extra]
  musicxml    [extra]
```

Every stage reads and writes the same Song IR, so each one can be run on its own,
inspected, or replaced by a plugin.

This covers releases P1 (MIDI), P2 (chord sheets with generated grooves) and P3 (tabs
and notation). Audio comes later; see `Strudelizer-PRD.md`.

## Install

Strudelizer needs Python 3.10 or newer. The core depends only on mido, PyYAML and
jsonschema. Two importers need an optional extra:

```sh
git clone <this repo> strudelizer && cd strudelizer
pip install -e .                    # MIDI, chord sheets, ASCII tabs
pip install -e ".[guitarpro]"       # + Guitar Pro .gp3/.gp4/.gp5 (PyGuitarPro)
pip install -e ".[musicxml]"        # + MusicXML .musicxml/.mxl (music21)
pip install -e ".[all]"             # everything, plus the dev tools
```

Without an extra, its importer is not registered, and `strudelize list` shows the
command that installs it.

## Quick start

These steps take about 2 minutes.

1. Convert a MIDI file, or turn a chord sheet into a full groove:

   ```sh
   strudelize song.mid -o song.js
   strudelize chords.txt --bpm 90 --style lofi -o song.js   # chords + bass + drums
   strudelize riff.txt -o riff.js                           # an ASCII tab
   strudelize song.gp5 -o song.js                           # Guitar Pro
   strudelize score.musicxml -o score.js                    # MusicXML (or .mxl)
   ```

   No file to hand? Use the test fixtures, such as `tests/fixtures/multitrack_repeats.mid`,
   `tests/fixtures/sheets/night_train.txt`, `tests/fixtures/tabs/riff.txt`,
   `tests/fixtures/gp/song.gp5` or `tests/fixtures/musicxml/score.musicxml`.

2. Open https://strudel.cc, replace the example code with the contents of `song.js`,
   and press **ctrl+enter** (**cmd+enter** on a Mac).

3. Try another sound profile or style:

   ```sh
   strudelize song.mid -o song.js --profile lofi                        # or techno
   strudelize chords.txt --bpm 120 --style four_on_floor -o song.js     # or rock
   ```

Here is a converted 7/8 groove:

```js
// Groove in 7/8
// Source: groove_78.mid
// Generated by Strudelizer 0.1.0 (profile: default)
setcps(140/60/7)

stack(
  // kit (drums)
  stack(
    s("bd ~ ~ ~ bd ~ ~"),
    s("~ ~ sd ~ ~ sd ~").velocity(0.91),
    s("hh*7").velocity(0.73)
  ).bank("RolandTR909"),
  // synth_bass (bass)
  note("<[d2@2 f2 ~ a2 c3@2] [d2@2 d2 ~ a2@3]>").s("sawtooth").lpf(800)
)
```

One bar is one cycle. Repeated bars collapse (`bar!7`, or a whole loop written once),
and each track gets its sound from the profile. When a song has sections, as chord
sheets usually do, each section becomes a `const` and the song ends with
`arrange([8, verse], [8, chorus], ...)`.

## Commands

| Command | What it does |
| --- | --- |
| `strudelize <in> -o out.js` | One-shot: import, run passes, emit. The `-o` extension picks the emitter: `.js` Strudel, `.mid` MIDI, `.json` IR. |
| `strudelize import <in> -o song.ir.json` | Input file to IR |
| `strudelize pass <ir> --passes SPEC -o out.ir.json` | Run passes on an IR file |
| `strudelize emit <ir> -o song.js [--profile P]` | IR to Strudel (or `.mid` / `--emitter ...`) |
| `strudelize list` | Installed importers, passes, emitters, profiles and styles |

Options for the one-shot form (`import` takes the importer ones too):

| Option | Meaning |
| --- | --- |
| `--passes SPEC` | Comma-separated passes. Default `quantize:16+8t,dedupe_bars`; `""` for none. |
| `--style NAME` | Run `arrange` first with a style (`lofi`, `rock`, `four_on_floor`, or a `.yaml` file). |
| `--profile NAME` | Sound profile (`default`, `lofi`, `techno`, or a `.yaml` file) |
| `--bpm N` | Tempo for inputs without one (chord sheets default to 100, with a warning) |
| `--beats-per-chord N` | Chord sheets: how long each chord lasts (default one bar) |
| `--pickup N` | Beats in a partial first bar. Overrides what the importer detects. |
| `--tuning "D A D G B E"` | Tabs: open strings, lowest first (or `drop d`, `dadgad`, …). Default: the string labels, else standard. |
| `--capo N` | Tabs and chord sheets: capo fret; everything sounds N semitones higher. |
| `--tab-rhythm MODE` | Tabs: `even8` (default, each note column an 8th), `even16`, or `columns` (spacing inside each bar). |
| `--strict` | Validate the IR after every pass, not only when it is read or written |

- **Pass specs.** A bare argument fills a pass's main option (`quantize:16`,
  `transpose:-2`); `name:key=value` sets any option.
- **Warnings and errors** go to stderr. Each error names the stage, the location (bar,
  line or file) and a fix when one is known:

  ```
  warning [import:chordsheet]: line 16: skipped unparsed line '| Cm | Fxx7 | G7 |': not chords: 'Fxx7'
  error [pass:quantize] at option grid='13': unknown grid '13'
    fix: use 4, 8, 16, 32, 8t or 16t, or combine with +, e.g. quantize:16+8t
  ```

### Passes

| Pass | What it does |
| --- | --- |
| `quantize:16+8t` | Snap to a grid: `8`, `16`, `32`, `8t`, `16t`, or combined with `+` |
| `dedupe_bars` | Mark identical bars so emitters can collapse them (run it last) |
| `arrange:lofi` | Generate missing drums and bass from a style. Slash chords: the bass plays the slash note and the chord drops it. |
| `detect_sections` | Name repeated multi-bar runs (`part_a`, `part_b`, …) for songs without sections, such as MIDI |
| `transpose:-2` | Shift notes, chords and the key by N semitones |
| `remap_drums:kit.yaml` | Rename or drop drums with a mapping file (`clap: snare`, `cowbell: null`) |

### Python API

```python
from strudelizer import Pipeline

code = Pipeline("chordsheet", "arrange:lofi,quantize,dedupe_bars", "strudel",
                importer_options={"bpm": 90}).run("chords.txt")
midi_bytes = Pipeline(emitter="midi").run("song.mid")
song = Pipeline(passes=None).load("song.mid")      # a Song (the IR)
print(song.to_json())
```

## Chord sheets

The `chordsheet` importer reads `.txt`, `.cho`, `.crd`, `.chopro` and `.chordpro`
files. Three notations work, and can be mixed in one file:

```
{title: Harbor Lights}                 ChordPro: inline chords, directives
{tempo: 92}
{start_of_chorus}
[Em]Harbor [Bm7]lights, [CM7]carry me [D7]home
{end_of_chorus}

[Verse]                                Chords over lyrics: a line of chords only
Am              Fmaj7
Paper kites above the station

Intro: | N.C. | Cm | Cmin | C- |       Bar lines: chords in a bar split it evenly
|: Cm7 | F7 :| Ab^7 / / G7 | Cm % |    / holds, % repeats the bar, |: :| repeats
```

- **Timing.** In ChordPro and chords-over-lyrics, each chord lasts one bar (or
  `--beats-per-chord`). Lyrics never take time.
- **Directives:** `{title}`, `{key}`, `{tempo}` and `{time: 3/4}`, plus section
  directives (`{start_of_chorus}` / `{soc}`, `{sov}`, `{sob}`, `{chorus}` to repeat the
  chorus). Section labels can also be written `[Verse]`, `Chorus:` or `Bridge 2:`.
- **Pickup:** `{x_pickup: 1}` (alias `{pickup: 1}`) or `--pickup 1`. The first chord, or first bar, lasts that
  many beats, and bar 1 starts on Strudel cycle 1.
- **Chord spellings:** all of these are accepted: `C`, `Cm`/`Cmin`/`C-`, `C7`,
  `Cmaj7`/`CM7`/`C^7`/`CΔ`, `Cm7`, `C6`, `Cm6`, `C9`, `Cadd9`, `Csus2`, `Csus4`,
  `Cdim`/`C°`, `Cm7b5`/`Cø`, `Caug`/`C+`, slash chords `C/E`, and more (`maj9`, `m9`,
  `6/9`, `7b9`, `11`, `13`, …). Each is stored in the IR as root, quality, extensions
  and bass.
- **Strict parsing.** A token is a chord only if it matches exactly, so lyrics are never
  read as chords. Lines that look like chords but don't parse (`Hm7`, `| Fxx7 |`, or an
  unknown `{directive}`) are reported with their line number and skipped.

## Tabs, Guitar Pro and MusicXML

**ASCII tabs** (`.tab`, or `.txt` files that are mostly tab) are blocks of 4 to 7 staff
lines, highest string first:

```
Tuning: Drop D
Tempo: 132

e|----------------|
B|----------------|
G|----------------|
D|0-0-3-0-5-3h5-0-|
A|0-0-3-0-5-3-5-0-|
D|0-0-3-0-5-3-5-0-|  x2
```

- **Tuning** comes from the string labels (drop D above), a `Tuning:` line, or
  `--tuning`. Standard tuning is the default for 4-string bass, 5-string bass,
  6-string guitar and 7-string guitar.
- **Capo** comes from a `Capo: 2` line or `--capo`.
- **Techniques** (`h p b r / \ ~`) are ignored, but their fret numbers are kept; a dead
  note `x` keeps its rhythmic slot and is silent. A trailing `x2` repeats the block.
- **Rhythm.** A tab has none, so `--tab-rhythm` picks one: `even8` (default) makes every
  note column an eighth note, `even16` a sixteenth, and `columns` places notes by their
  position inside each `|` bar.
- **In chord sheets,** tab blocks (`{start_of_tab}` … `{end_of_tab}`, or bare blocks)
  become a tab track and take their own bars in the song. `{capo: N}` applies to both the
  chords and the tab.
- **Broken lines** that look like tab but don't parse are reported with their line number.

**Guitar Pro** files (`.gp3` to `.gp5`, with the `guitarpro` extra):

- Every track becomes a track. Pitch is the string tuning plus the fret plus the
  track's capo, and percussion tracks become drum hits.
- Repeats and alternate endings are played out in order, and markers become sections.
- Tied notes are held; dead notes and grace-note ornaments are left out. Other
  techniques (bends, slides, vibrato, harmonics) are ignored.

**MusicXML** (`.musicxml`, `.mxl` or `.xml`, with the `musicxml` extra):

- Parts become tracks, and harmony symbols become chord events.
- Repeats and endings are played out, and tied notes merge into one.
- An implicit short first measure is a pickup.

In all three formats, tempo or meter changes use the dominant value with a warning,
as for MIDI.

## Styles

A style is a YAML file of step patterns, one character per step: `x` hit, `X` accent,
`g` ghost, `.` rest. Patterns are given per time signature:

```yaml
name: mine
bass: { rule: root_fifth, octave: 2 }   # root | root_fifth | root_octave
meters:
  "4/4":
    steps: 16
    drums:
      kick:  "x . . . . . . x . . x . . . . ."
      snare: ". . . . X . . . . . . . X . . ."
    bass:    "x . . . . . . x . . x . . . . ."
    chords:  null                       # or a rhythm to re-strike chords on
```

`arrange` only fills in what is missing: drums when there are none, and a bass that
follows the chord symbols when there is no bass. The built-in `lofi`, `rock` and
`four_on_floor` styles cover 4/4 and 3/4.

## Sound profiles

A profile is a YAML file that maps roles and drums to Strudel sounds. Effects are
applied in order:

```yaml
name: mine
drums:
  bank: RolandTR909                # Strudel drum-machine bank
  map: { kick: bd, snare: sd:2 }   # anything left out uses the defaults; null drops a drum
  unbanked: [cowbell, tambourine, shaker]   # not in this bank: play from the default kit
  fx: [ { room: 0.2 } ]
roles:
  bass:   { sound: sawtooth, fx: [ { lpf: 800 } ] }   # -> .s("sawtooth").lpf(800)
  melody: { sound: square }
  other:  { sound: triangle }                          # fallback for missing roles
```

## The Song IR

The IR is a JSON document checked by the schema in
[`strudelizer/core/schema.json`](strudelizer/core/schema.json), currently version 2.
The Python side is frozen dataclasses in `strudelizer/core/ir.py`.

```json
{
  "version": "2",
  "meta": { "title": "Night Train", "bpm": 90, "time_signature": [4, 4], "key": "Cm",
            "source": "night_train.txt", "pickup_beats": "2" },
  "sections": [ { "name": "verse", "start_bar": 4, "length": 16 } ],
  "tracks": [
    {
      "id": "chords", "role": "chords",
      "events": [
        { "type": "chord", "start": "2", "duration": "4", "symbol": "Cm7",
          "root": "C", "quality": "m7", "pitches": [48, 51, 55, 58] },
        { "type": "note", "start": "6", "duration": "1/3", "pitch": 62, "velocity": 90 },
        { "type": "hit", "start": "8", "drum": "kick", "velocity": 110 }
      ]
    }
  ]
}
```

- **Times are beats, written as exact fractions** (`"0"`, `"1/3"`, `"7/2"`), so
  triplets survive round trips. One beat is the time signature's denominator unit: an
  eighth note in 7/8, where `bpm` counts eighths. A bar is `time_signature[0]` beats.
- **`pickup_beats`** marks a partial first bar. Time 0 is the start of the pickup, bar 1
  starts at `pickup_beats`, and in `sections` bar index 0 is the pickup bar.
- **Only `tracks[].events` is required.** Missing values fall back to defaults:
  120 bpm, 4/4, role `other`.
- **Event types** are:
  - `note`: start, duration, MIDI pitch, optional velocity
  - `hit`: start, drum, optional velocity
  - `chord`: start, duration, symbol, root/quality/extensions/bass, optional pitches
- **Drum names:** `kick snare closed_hat open_hat clap rim tom_low tom_mid tom_high
  crash ride cowbell tambourine shaker`.
- **`role`** is one of `drums bass chords melody vocal other`.
- **`bars`** is written by `dedupe_bars`. Entry *i* is the first bar identical to bar
  *i*.
- **Extensions:** keys starting with `x-` are allowed on the song and on tracks, and
  are preserved.
- **Version 1 files** (before pickups) load unchanged and are saved as version 2.

The IR is schema-checked whenever it is read from or written to a file. `--strict`
also checks it after every pass.

## Known limitations

- **Very long held notes are re-attacked.** A note tied across bar lines is held: the bars
  it joins are written as one multi-cycle step. A run is capped at 4 bars and always
  breaks at a section start, so a note held longer than that sounds again at the break.
- **Tempo changes use the dominant tempo.** A MIDI file with several tempos converts
  at the one that covers the most of the song, with a warning. Meter changes work the
  same way.
- **Pickups are only detected in MIDI files that write them as a short first bar**
  (e.g. 1/4 then 4/4), as notation programs do. A pickup written as a full first bar of
  rests is not detected; pass `--pickup`.
- **Styles generate full bars only**, so the pickup bar plays its chords without drums
  or bass. Styles cover 4/4 and 3/4.
- **Some chords have no name in Strudel's voicing dictionary,** and slash chords can't
  be voiced from it. These are written as explicit note stacks.
- **No dynamics on chord tracks:** chord sheets carry no velocity.

## Writing an importer plugin

Plugins are found only through Python entry points, and the built-ins are registered
the same way. A new input format is one module plus one entry-point line, with no
change to Strudelizer itself.

```python
# my_tabs/importer.py
from fractions import Fraction
from strudelizer.core import Meta, Note, Song, Track
from strudelizer.registry import Importer

class TabImporter(Importer):
    """ASCII guitar tab (.tab), one note per 8th."""   # first line shows in `strudelize list`

    name = "mytab"
    extensions = (".tab",)          # can_handle() checks these by default

    def load(self, path, options):  # options: --bpm, --pickup, ... as a dict
        notes = []
        for i, fret in enumerate(open(path).read().split()):
            notes.append(Note(start=Fraction(i, 2), duration=Fraction(1, 2), pitch=40 + int(fret)))
        return Song(meta=Meta(title="My tab", bpm=options.get("bpm", 100), time_signature=(4, 4)),
                    tracks=(Track(id="guitar", role="melody", events=tuple(notes)),))
```

```toml
# my_tabs/pyproject.toml
[project.entry-points."strudelizer.importers"]
mytab = "my_tabs.importer:TabImporter"
```

After `pip install -e my_tabs`, `strudelize list` shows `mytab`, and
`strudelize song.tab -o song.js` works.

- **Validation is automatic.** The pipeline checks your Song against the schema. To
  report a problem, raise
  `strudelizer.core.StrudelizerError(stage, message, location=..., fix=...)`.
- **Other plugin types work the same way.**

  | Group | Base class | Method | Rules |
  | --- | --- | --- | --- |
  | `strudelizer.passes` | `Pass` | `run(song, options) -> Song` | Pure: return a new Song with `dataclasses.replace`. Drop `track.bars` if you change events. |
  | `strudelizer.emitters` | `Emitter` | `emit(song, options)` | Returns `str`, or `bytes` with `binary = True`. Set `extension` so `-o` can pick it. |
  | `strudelizer.profiles`, `strudelizer.styles` | none | a zero-argument callable | Returns the mapping. |

- **A plugin that needs an extra** declares it on its entry point,
  `mytab = "my_tabs.importer:TabImporter [tabs]"`, and lists the modules it imports in
  `requires = ("some_library",)`. Import those modules inside `load()`, not at the top of
  the file. Until they are installed, the plugin is not registered, and `strudelize list`
  shows the `pip install "my-tabs[tabs]"` command.

## Development

```sh
pip install -e ".[all]"           # dev tools plus the guitarpro and musicxml extras
python scripts/check.py           # lint + tests (strict) + Strudel check; installs the
                                  # pinned Strudel runtime with npm ci on first run
python scripts/check.py test -k chordsheet    # or: lint | test [pytest args] | strudel
python tests/bench_dense.py       # NFR-6 timing on a dense 5-minute song
```

`make check`, `make test` and the other Makefile targets just call `scripts/check.py`.

The test suite covers:

- unit tests for every stage;
- golden files for every fixture: MIDI songs, and chord sheets with and without each
  style;
- the MIDI → IR → MIDI → IR round trip, which must match the source at least 98%;
- byte-for-byte determinism across processes;
- the release gates: every generated `.js` is evaluated with `@strudel/*` 1.2.6 in
  Node, queried for the whole song, and compared event by event with the IR.

The fixtures live under `tests/fixtures/`:

- `make_fixtures.py` regenerates the MIDI fixtures.
- `sheets/` holds the hand-written chord sheets.
- `STRUDELIZER_UPDATE_GOLDEN=1 pytest tests/test_golden.py` rewrites the golden files.
  Review the diff after running it.
